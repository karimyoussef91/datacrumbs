# I/O Roofline Model

This document explains how the I/O roofline for this node was generated:
which benchmarks produced each parameter, how the trace-derived points were
computed, and what the results mean.

## Model

Follows Zhu & Neuwirth, *Characterization of Large-scale HPC Workloads with
non-naive I/O Roofline Modeling and Scoring* (ICPADS'23), with the axis
convention also used in Tang et al., *Quantifying AWS S3 I/O Performance
Boundaries Using the Roofline Model* (SC Workshops'25):

```text
Attainable Performance (IOPS) = min(psi, kappa * IOI)
IOI (I/O operational intensity) = theta / sigma
```

- `psi` — peak IOPS (system-specific, from a benchmark sweep)
- `kappa` — peak I/O bandwidth in bytes/s (system-specific, from a benchmark sweep)
- `theta` — count of traced I/O operations for one interface (POSIX or MPI-IO)
- `sigma` — total bytes moved by the workload
- `IOI` is IOP/byte on the x-axis; attainable IOPS is on the y-axis (both log-scaled)

The ridge point is `psi / kappa`, the I/O intensity where the system stops
being IOPS-bound and becomes bandwidth-bound.

## System Parameters (psi, kappa): IOR Benchmark Sweep

Script: [`scripts/run_io_roofline_benchmark.sh`](scripts/run_io_roofline_benchmark.sh)

It runs the installed IOR binary (`$HOME/.local/ior/bin/ior`) across all 24
physical cores (both sockets), using `mpirun --bind-to core`, with two
configurations:

1. **Peak-IOPS run**: small transfers, high parallelism, file-per-process
   ```bash
   mpirun -np 24 --bind-to core ior -a POSIX -b 4k -t 4k -s 100 -F -w -r -e -o <path>
   ```
2. **Peak-bandwidth run**: large sequential transfers
   ```bash
   mpirun -np 24 --bind-to core ior -a POSIX -b 4m -t 4m -s 20 -F -w -r -e -o <path>
   ```

The script parses IOR's own `bw(MiB/s)` and `IOPS` columns from both runs and
takes the maximum of each across both write and read phases:

```text
peak_iops      = 989320.00 IOP/s
peak_bandwidth = 70.3816 GB/s
```

**Caveat**: this IOR sweep does not use `O_DIRECT`, so `peak_iops` reflects
page-cache-assisted small-I/O performance, not the raw device's IOPS ceiling.
The honest device-level bandwidth reference is the `fio --direct=1` result in
[`data/storage.csv`](data/storage.csv) (`0.4108`/`0.4737` GB/s read/write),
generated separately by [`scripts/run_nvme_roofline.sh`](scripts/run_nvme_roofline.sh)
for the FLOP-based roofline model.

Roofline-only figure: [`scripts/plot_io_roofline.py`](scripts/plot_io_roofline.py)
reads `data/io_roofline_system.csv` and plots the `psi`/`kappa` roofs and
ridge point with no application points:

```bash
python3 scripts/plot_io_roofline.py --output io_roofline_model.png
```

## Application Points (theta, IOI, IOPS): DataCrumbs Trace

Script: [`scripts/analyze_io_roofline.py`](scripts/analyze_io_roofline.py)

The three points come from one DataCrumbs trace of a 2-rank IOR MPI-IO run,
so `sigma` (32 MiB total) is identical for all three; only `theta` and the
elapsed time differ per layer.

### Workload traced

```bash
mpirun -np 2 -x LD_PRELOAD ior -a MPIIO -b 4m -t 1m -s 2 -F -w -r -e \
  -o "$HOME/traces/work/ior-mpiio-2rank-v2"
```

### Probe used

`$HOME/traces/probes/ior-mpiio-syscalls.json`, generated by
[`scripts/testing/generate_core_only_mpiio_probe.py`](../scripts/testing/generate_core_only_mpiio_probe.py),
combining:

- POSIX syscalls: `read`, `write`, `openat`, `close`, `fsync`
- MPI-IO uprobes on `libmpi.so.40`: `MPI_File_open/close/read/read_at/read_all/read_at_all/write/write_at/write_all/write_at_all/iread/iread_at/iwrite/iwrite_at`

The trace observed 9,614 events; the MPI-IO layer specifically hit
`MPI_File_open`, `MPI_File_read_at`, `MPI_File_write_at`, `MPI_File_close`
(IOR's MPIIO backend uses the `_at` positioned variants, not the plain
sequential-pointer calls).

### Derivation (`scripts/analyze_io_roofline.py`)

For each layer: `theta` = count of matching trace events, `IOI = theta/sigma`,
`IOPS = theta / elapsed_seconds`, where `elapsed_seconds` is either the
application's own wall-clock phase time (write + read, from IOR's reported
`wr/rd(s)` columns) or the cumulative traced-event duration for that
interface (overhead-inclusive):

```bash
python3 scripts/analyze_io_roofline.py \
  --trace /home/cc/traces/26/08/20/trace-cc-mpi-io-2rank-v2-xio-rooflines-ior-mpiio-syscalls.pfw.gz \
  --workload-bytes 33554432 \
  --application-seconds 0.056642
```

Output: [`data/io_roofline_points.csv`](data/io_roofline_points.csv)

| Layer | theta (ops) | IOI (IOP/byte) | IOPS | Elapsed time (s) | Semantics |
| --- | ---: | ---: | ---: | ---: | --- |
| `overall_application` | 9614 | 2.865e-4 | 169732.7 | 0.056642 | IOR write+read wall-clock time; theta = POSIX + MPI-IO ops |
| `mpi_io` | 54 | 1.609e-6 | 1340.3 | 0.040289 | Cumulative traced `MPI_File_*` duration; overhead-inclusive |
| `posix` | 9560 | 2.849e-4 | 38939.0 | 0.245512 | Cumulative traced POSIX syscall duration; overhead-inclusive |

The `mpi_io` layer's IOI is roughly two orders of magnitude lower than the
POSIX/application layers: IOR issued only 54 MPI-IO calls total for the same
32 MiB, versus thousands of underlying POSIX syscalls, since each MPI-IO
call moves many bytes at once.

## Final Figure

```bash
python3 scripts/plot_io_roofline.py \
  --points data/io_roofline_points.csv \
  --output io_roofline_three_points.png
```

[`io_roofline_three_points.png`](io_roofline_three_points.png) shows the
`psi`/`kappa` roofs, the ridge point (`1.406e-5` IOP/byte), and all three
trace-derived points. All three points sit well below the ridge point,
meaning this workload is far from saturating either the IOPS or bandwidth
ceiling of this node.

## Reproduce End to End

```bash
bash scripts/run_io_roofline_benchmark.sh
python3 scripts/plot_io_roofline.py --output io_roofline_model.png

# (separately: generate a DataCrumbs POSIX+MPI-IO trace of an IOR -a MPIIO run;
#  see /home/cc/datacrumbs/steps_to_run.md for the exact probe/run/stop steps)

python3 scripts/analyze_io_roofline.py \
  --trace <path-to-mpiio-trace>.pfw.gz \
  --workload-bytes <bytes> \
  --application-seconds <write+read-wall-seconds>

python3 scripts/plot_io_roofline.py \
  --points data/io_roofline_points.csv \
  --output io_roofline_three_points.png
```
